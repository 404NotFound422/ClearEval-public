# ClearEval 技术堵点的文献调研与模块化改造方案

**阅读顺序更新：** 按用户要求，先读以十个真实问题为单位的 [细节诊断主报告](CASES_zh.md)。本文件保留为文献与技术模块索引；模块由具体反例推导，不作为研究起点。

调研日期：2026-10-12。状态：技术研究完成；本报告中的新模块设计尚未实现或验证。研究期间没有新增评价器请求、重评分或专家记录。原实验调用账本仍为 438/438。

## 1. 技术判断与推荐路线

建议将下一阶段工作的中心放在**有来源的协议表示与分项评分契约**。让大模型负责读懂和分解全文，用明确的证据记录连接到既有评分函数，再用受控实验判断每一层是否可靠。这能统一处理目前分散在步骤、标签、时间和 Cor 中的问题。

本次找到非常接近的已发表工作 **Thoth/SCORE（ICLR 2026）**：它已经采用动作、对象、参数的结构化分解，并评价粒度、顺序和语义。因此，“用 LLM 分解 protocol”或“增加步骤图”本身不能作为我们的创新主张。ClearEval 值得验证的差异是：在真实自由文本、中文回答、多个合理完整路线和不完整适用证据下，能否忠实恢复评分输入，保留原 SR/SP 与 EGES，并解释各项分数及联合结论为什么改变。[正式会议记录](https://proceedings.iclr.cc/paper_files/paper/2026/hash/7721f1fea280e9ffae528dc78c732576-Abstract-Conference.html)、[方法全文](https://arxiv.org/html/2510.15600v1)。

| 堵点 | 可借鉴的文献模块 | ClearEval 拟形成的模块 | 优先级 |
|---|---|---|---|
| JSON 有效却没有保留取值依据；跨句关系丢失 | PEG 协议图、结构化解码、来源归因 | M1：带原文绑定的轻量协议中间表示 | 第一批 |
| 中文匹配低；同一步匹配多个不同参考操作 | 多语言嵌入、SCORE 动作锚点、原子事实支持 | M2：跨语言候选召回＋操作实例覆盖判断 | 第二批 |
| 只给方法名、多个版本；合理替代路线不应受罚 | 多参考评估与参考集敏感性 | M3：完整路线内选参考＋版本影响审计 | 第二批 |
| MAP2、染料、GFP、所选/提及和组织范围混淆 | 类型关系图、来源及作用域记录 | M4：标签关系与条件化知识查询 | 第一批 |

| LLM 越界做数值有效性裁判；有依据却不给分 | 显式评价准则、证据归因、测量有效性 | M6：逐判项证据记录＋确定性原公式 | 第一批 |

| 排名受阈值、时间分支、共同题集左右 | 多路径分析、稳健多目标分析 | M8：一致场景下的 CCE/Pareto 与配对重采样 | 第三批 |

## 3. M1：带原文绑定的协议中间表示

**问题。** 当前几个脚本分别解释标题、步骤、标签和时间。同一段话经过多次局部解析，容易出现“时间挂错步骤”“正文提及被当成所选标签”“从参考补出答案没有说的内容”。继续增加局部规则会增加解释不一致的机会。

**文献提取。** Tamari 等的 PEG 将协议表示为动作、实体及跨句关系，允许自然语言保留不完整性；Kulkarni 等研究跨动作短语的潜在结构。两者说明协议信息并不天然等于逐行列表。AIS 则将内容是否可解释与能否由外部来源支持区分开。[PEG，EACL 2021](https://aclanthology.org/2021.eacl-main.187/)、[跨动作结构，ACL 2021](https://aclanthology.org/2021.acl-long.525/)、[AIS，Computational Linguistics 2023](https://aclanthology.org/2023.cl-4.2/)。

**拟用模块。** LLM 读取完整答案，生成轻量 JSON 图，至少包含：

- 原文实体和操作实例；实体类型；前后依赖；标签关联；参数归属；初始条件、正文操作和可选分支。
- 每个事实附 `unit_id + quote + occurrence`。程序定位字符范围并核对源文件哈希，避免让模型自行计算字符偏移。
- 规范化值保留原文字面值；区分“答案明确报告”“题干已给”“根据已批准约定换算”“仍含歧义”。参考库的事实另存，不写回答案事实。
- 不能解释的局部事实附具体原因，其他已确定事实仍输出。随后每个评分分项只检查自己的输入依赖。

示例数据结构仅用于解释接口，不是新实验输出：

```json
{
  "fact_id": "F_label_01",
  "kind": "label_relation",
  "target": "MAP2",
  "fluorophore": "Alexa Fluor 488",
  "antibody_chain": "not_specified",
  "evidence": [{"unit_id": "L0012", "quote": "MAP2+Alexa Fluor 488", "occurrence": 0}],
  "origin": "answer_explicit",
  "downstream_uses": ["label_compatibility"]
}
```

该结构允许评价已有目标—荧光关联，同时不编造一抗宿主、克隆或二抗链。`antibody_chain` 未说明本身不应阻断根本不需要它的查表通道。

**可实现性。** Ollama 原生接口支持 JSON Schema；XGrammar 提供结构约束解码的技术依据，但不能据此声称本地 Ollama 使用了 XGrammar。LangExtract 的来源定位思路可用，不过当前官方文档明确其 Ollama provider 不支持自定义 `output_schema`，不能把库支持与底层原生能力混为一谈。[Ollama 文档](https://docs.ollama.com/capabilities/structured-outputs)、[XGrammar，MLSys 2025](https://proceedings.mlsys.org/paper_files/paper/2025/hash/5c20ca4b0b20b0bd2f1d839dc605e70f-Abstract-Conference.html)、[LangExtract 输出模式](https://github.com/google/langextract/blob/main/docs/examples/output_schema.md)。

最小实现建议直接复用当前 Qwen 客户端、来源文件和定位函数，再加统一的数据结构；不必先引入图数据库或重训协议图模型。先试原生 Schema 的实际支持程度，不能把“接口文档支持”写成“本机已验证”。

**可能贡献与验证。** 创新候选是把协议语义图用于忠实恢复评分输入并追踪分项依赖，局部未知只影响相应输入。与逐行提取比较来源支持率、重要关系遗漏率和最终 EGES 差异；由共用的 5＋15 核查确认语义，不以 JSON 成功率代替准确率。

## 4. M2：跨语言召回与操作实例覆盖判断

**问题的形式化。** 原 SR/SP 是相似度矩阵逐行、逐列最大值越过阈值后的比例：

\[
SR=\frac1m\sum_i\mathbf1[\max_j s(r_i,g_j)\ge\delta],\quad
SP=\frac1n\sum_j\mathbf1[\max_i s(r_i,g_j)\ge\delta].
\]

由定义可知，步骤置换不改变结果；一个生成步骤可同时支持多个参考行。SR 本来就不负责顺序；顺序问题应交给 `co_order`。删掉未命中的生成步骤可能提高 SP，因为分母也变了。这两种现象不能直接当成程序错误。[BioProBench 原文](https://arxiv.org/html/2505.07889v4)、[作者指标代码](https://raw.githubusercontent.com/YuyangSunshine/bioprobench/main/Metrics/GEN.py)。

**文献提取与取舍。** Multilingual E5、BGE-M3 和 Qwen3-Embedding 提供跨语言召回能力；SCORE 提供动作锚点思路；FActScore 提供原子化后查证的思路；AlignScore 强调支持关系的方向。嵌入相关性不是操作覆盖证明，FActScore 的事实精确率也不等于必要步骤召回率。AlignScore 仍包含最大值聚合，不能单独解决多对一覆盖。[E5](https://arxiv.org/abs/2402.05672)、[BGE-M3，Findings ACL 2024](https://aclanthology.org/2024.findings-acl.137/)、[Qwen3-Embedding](https://arxiv.org/abs/2506.05176)、[FActScore，EMNLP 2023](https://aclanthology.org/2023.emnlp-main.741/)、[AlignScore，ACL 2023](https://aclanthology.org/2023.acl-long.634/)。

**拟用模块。** 对参考操作召回少量候选，再根据动作、对象、阶段和原文证据判断覆盖。建立操作实例 ID：一条合并句如果明确表达四次不同操作，可分解为四个实例；一句仅说“孵育”不能自动覆盖四次操作。区分同一操作的重复提及与实际重复执行。数值在这里可以帮助识别“第几次/哪一个操作”，对其是否适宜的数值判断仍由 EGES 承担。

不在原始段落之间强制一对一匹配；那会错误惩罚合法合并。也不允许一个缺乏内部结构的实例无限承接参考操作。提取歧义保留在局部覆盖记录中，不能通过参考内容补全截断答案。

**具体实施选项。** 开发阶段先选一个多语言候选，避免同时试遍模型并挑最好看的结果。E5-base 较轻；对称相似度应按官方模型卡在两侧都使用 `query:`，且其相似度分布与 MPNET 不同，不能直接沿用 0.7。BGE-M3 可先只用 dense 模式。Qwen3-Embedding-0.6B 是另一个候选，但官方要求的 transformers ≥4.51 高于本地 4.48.3，需独立环境。嵌入模型与用户要求的 Qwen 评价器是两个不同角色。[E5 模型卡](https://huggingface.co/intfloat/multilingual-e5-base)、[BGE-M3 模型卡](https://huggingface.co/BAAI/bge-m3)、[Qwen 模型卡](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B)。

**创新边界。** 多语言嵌入、动作分解、顺序匹配都已有先例；ReGraph 也已研究程序性图结构的评价，但目前核实的是 2026 年预印本。值得检验的是“来源可核对的操作实例覆盖”能否同时消除中文、拆合和重复操作带来的偏差。[ReGraph](https://arxiv.org/abs/2608.06917)。

**实验。** 在同一开发材料上拆分三步消融：只换编码器；只增加操作实例表示；再增加覆盖支持判断。对等义翻译/编号/拆合期待近似不变，对必要操作删除期待覆盖降低。保留原 `sr`、`sp`，新增指标命名为 `semantic_coverage` 等，未经定义确认和验证不替换 Com 中的 SR。

## 5. M3：完整路线内选参考与版本影响审计

**回答用户此前的问题。** 只给方法名称时，可以比较当前参考库中该方法下、适用于该任务的所有完整版本，按最高 SR、同一参考的 SP、固定版本顺序选取。这已是 r2 的规则。这里的“全部”是冻结清单中的全部已收录、来源完整且适用的版本，不能声称穷尽该方法的所有文献。

**问题。** max-SR 随候选参考增多不会下降，因此不同方法的参考数量、重复版本和范围不一致可能影响可比性。不能逐个步骤从不同版本取最大值拼出不存在的路线，也不能因为答案时间、浓度有错误就提前排除对应路线。

**文献提取。** INLG 2025 的 References Matter 研究参考集变化如何影响评价；它提供的是参考敏感性警示，不是组织透明多路线有效性的直接证明。[正式论文](https://aclanthology.org/2025.inlg-main.18/)。SCORE 的顺序和步骤比较可作为结构诊断，但其单参考设定本身不能解决 ClearEval 的任务适用性和合理第二路线问题。

**拟用模块。** 每份答案保存全部相容版本的 SR/SP、所选版本、次优差距和适用依据。先按方法身份与任务条件筛选，再做 max；所选完整参考用于同一条记录的 SR/SP。对并列与近并列、来源家族和重复版本做显式标记。对参考数不同的方法，报告逐版本结果及预先确定的参考子集敏感性，不根据最终模型排名反向挑选清单。

例如同为 FDISCO 的两个完整版本，答案更接近版本 B，就选 B；若答案选择有适用证据的另一方法，则在该方法自己的完整参考中选择。两条路线可能都完整且合理，Eff 因任务目标而不同。合理替代不要求三维分数或 HV 完全相等。

**验证。** E2 分开做“同方法版本选择”与“不同方法完整替代”两组。必要操作删除必须覆盖每个相容版本并清除重复表述，否则 max-SR 转选另一合法版本不构成漏检。按 r2 目标准备 6–8 个完整替代路线对，实际来源不足的对保留待定。完整参考确认的人力独立记账，不能挤入 20 份答案核查后声称没有额外成本。

## 6. M4：标签角色、作用域和知识查询

**问题。** 已发生的错误包括：将 MAP2 当成必须完整解析的一抗；给原生 GFP 强行要求外部 marker；把末行 null 覆盖同名但不同组织范围的已知知识；把正文提及当成明确选择。它们属于类型或查询条件问题，增加模型推理长度不能自动修好错误索引。

**文献提取。** PEG 的类型与关系适合表达实体角色；W3C PROV-O 提供来源、处理过程和派生关系的标准概念。这里只需借用结构，不必建立大型知识图谱。[PEG](https://aclanthology.org/2021.eacl-main.187/)、[PROV-O](https://www.w3.org/TR/prov-o/)。

**拟用模块。** 将标签记录拆成 `target / antibody / fluorophore / native_signal`，并区分 `selected / mentioned / alternative`。查表使用方法、任务组织/尺度、目标、荧光、证据版本组成的复合条件，返回匹配行、适用依据和值。多条候选相互冲突时保留冲突，而不是最后一条覆盖前面结果。

三个直接例子：

1. `MAP2 + AF488`：可以确认目标与荧光关联；是否直接偶联、哪种二抗仍可能未说明。只有确实依赖那些信息的判项才需要它们。
2. `GFP`：按原生荧光通道处理；不适用的抗体靶标通道不进入内部最小值。
3. `AF594`：先查精确证据；使用用户允许的 AF 家族近似时，记录 `family_proxy`、采用规则与值的出处。家族近似不能写成每种染料性能完全相同的科学事实。

缺失知识记为 `reference_insufficient`，不能等同不兼容。适用通道已有可信的 0 时，原内部最小值规则仍能确定标签分为 0；没有证据的未知不能伪造为 0。

**可检验改进。** 在相同知识表上比较旧字符串查询、加入类型、再加入作用域三种设置。主终点是经核查关系/查询是否正确及分项变化，不是仅看缺值数量下降。现有 `cce_selected_label_source_v1.py`、`cce_typed_label_scorer_v2.py` 和 `cce_scoped_midpoint_scorer_v1.py` 可复用。

## 7. M5：时间语义账本与分支内计算

**问题。** 同一个数字可能表示每次时长、总时长、到某时刻的累计量或再次执行的间隔；“可选”又是路线分支。此前 C04 从 150 h 改为 72 h 涉及计时范围；FPC13 从 134 h 改为 158 h 涉及累计时长解释。这些并非仅靠提取全部数字再相加就能解决。[自动时间报告](../automatic_time_scope/REPORT_zh.md)。

**文献提取。** Dechter、Meiri、Pearl 的时间约束网络将时间点之间的关系写成区间约束；单一区间的简单时间问题与存在析取的情形不同。这适合组织时间关系，但不会替我们决定论文要计哪个阶段。[Temporal Constraint Networks，Artificial Intelligence 1991](https://www.sciencedirect.com/science/article/pii/0004370291900066)。

**拟用模块。** 保留操作的时间类型、重复次数、范围、分支、前后约束及证据。固定 EGES 当前口径为已报告的核心孵育范围。串行核心操作可求和；累计总量替代相应前段量；重复间隔不另加；题干已经完成的操作属于初始条件。原答案出现并行时，应先辨认原函数需要的量，不能擅自将当前累加口径改成关键路径耗时。

区间 \([l,u]\) 在一个明确分支内可按已约定中点 \((l+u)/2\) 给定值，同时保留端点敏感性。计算的是原函数 \(f((l+u)/2)\)，通常不等于 \((f(l)+f(u))/2\)。这是一项报告约定，不是已经观测到真实实验时间。

**区间与分支必须区别。** C08 的 20 h / 32 h 对应不采用/采用可选步骤；26 h 可能不对应任何原文路线，不能以“取中位数”合并两者。C05 有 14、17、18、21 h 四个分支内代表值，应分别计算。C02 的一个分支可算，另一个缺局部时长：前者仍输出，后者仅保留依赖缺口。

当前配置还有无数值定义的 `overnight=8 h` 约定。新表示应将其标成配置换算来源，区别于答案明确报告的 8 h；若评价该约定的敏感性，所有受影响答案使用同一设置，不能逐答案选有利值。

**验证。** 从已有错误中抽取每次/总计、累计/新增、间隔/时长、核心/标签准备、可选/必选五类最小对照。只改变表达、不改含义时结果应一致；真正改变时间或分支时按原函数响应。先核验逻辑，再用共用专家字段核查时间归属。复用 `cce_source_time_ledger_v1.py`，逐步让规则产生候选、统一语义表示作最终输入。

## 8. M6：逐判项证据与确定性原公式

**评分职责。** 按用户澄清，参数完整性判断必要字段是否提供；Cor 的 LLM 负责结构、顺序、方法逻辑及化学安全常识；具体数值适配由 EGES 的既有证据与函数负责。原量表、权重和归一化保留。此前 prompt 含数值偏差条款，后来又加入原版没有的 `UNCERTAINTY CONTRACT`，因此修订后的 prompt 必须单独版本化，旧 Cor 不能自动称作新职责下的结果。[原 prompt 核对](../missing_score_diagnosis/SCOPE_CORRECTION_zh.md)。

**文献提取。** G-Eval 表明明确准则与结构化判分过程可以用于 LLM 评价；MT-Bench 的研究也提示位置、冗长和偏好偏差仍存在。测量有效性研究要求说明判项到底测什么，不能把格式可解析或与自身稳定等同于领域正确。[G-Eval，EMNLP 2023](https://aclanthology.org/2023.emnlp-main.153/)、[judge 偏差，NeurIPS 2023](https://papers.neurips.cc/paper_files/paper/2023/hash/91f18a1287b398d378ef22505bf41832-Abstract-Datasets_and_Benchmarks.html)、[构念有效性，NeurIPS 2025](https://papers.neurips.cc/paper_files/paper/2025/file/1967e0fc3aa6cbbace562f5cb8e3954e-Paper-Datasets_and_Benchmarks_Track.pdf)。

**拟用模块。** 每个判项输出 `criterion_id、适用性、答案证据、必要参考证据、简短判定理由、档位、未决依赖`。保存的是可核对的判分依据，不要求隐藏推理链。所有答案采用冻结准则；不让模型按答案临时发明量表。禁止把比较答案、参考或上下文中的数值冒充被评答案的数值。

分数生成沿用：

\[
Com=0.4SR+0.6c_{param}/3,
\]
\[
Cor=(co_{order}/3+co_{method}/2+co_{param}/2+co_{chem})/4,
\]
\[
Eff=\big((s_{method}/2.5+1)/2+s_{label}/6+s_{trans}/3+s_{time}/3\big)/4.
\]

一个输入未知时保留其他分项；不能为了获得完整率而补造数值，也不能因一个未决标签清空整份答案。适用且根据量表确实应得 0 的情况正常给 0。

**验证。** 在同一全文、同一参考上下文上比较旧职责 prompt 与新冻结职责 prompt，检查数值越界、判项依据、档位一致性和专家一致性。新增定性 Cor 批目前实际仍为 0/10，不能声称已完成对照。使用用户指定的本地 Qwen 配置；第二 judge 必须是真实可调用、身份独立的允许模型，不能将同一模型两个角色当成跨家族结果。

## 9. M7：行为验证和稳定性分层

**文献提取。** CheckList 将行为测试分为最小能力、等义不变与方向响应；最新 EvalEval 2026 的证据稳定性研究区分文档身份与具体引用片段身份。两者使我们能问“哪一层在变”，而不是只看总分。[CheckList，ACL 2020](https://aclanthology.org/2020.acl-main.442/)、[Document Overlap Is Not Evidence Continuity，EvalEval 2026](https://aclanthology.org/2026.evaleval-1.35/)。

**拟用模块。** 把管线拆成六层记录：原文与分割；操作/关系提取；参考选择；证据查询；Cor 判项；确定性计算。受控实验始终对编辑后的全文重新提取和评分；随后可以固定中间表示，仅为定位原因做组件实验。两种结果分别报告。

| 验证类型 | 例子 | 正确的预期 |
|---|---|---|
| 最小能力 | 截断的“Incubation with” | 新覆盖模块不能由参考自动补出完整操作；原 SR 反例照实保留 |
| 等义不变 | 编号、格式、确定等义的单位换算 | 语义输入与相应判项不应改变 |
| 粒度诊断 | 完整操作合并为一句再拆开 | 新操作实例覆盖应尽量不变；原 SR/SP 的漂移单列 |
| 必要性响应 | 删除所有相容路线都必需的操作，并移除重复表述 | 必要覆盖应降低；不能强求 SP 一定降低 |
| 依赖顺序 | 交换确有前后依赖的两个操作 | Cor 顺序应响应；独立操作换序不一定有错，SR 不负责检测 |
| 合理替代 | 有来源的另一条完整路线 | 不因偏离唯一模板而受不当惩罚；Eff 可以不同 |

**稳定性的四个问题分别回答。** 同一 judge 真重复是否一致；不同 judge 是否一致；等义表达是否一致；与专家核查是否一致。前两种一致并不保证后者。固定表格重算和缓存命中是复现检查，不产生新的评价器重复。

重复统计同时报告有效分项数、NA 转换、档位翻转、参考切换、来源片段变化与分数极差。片段哈希变化只表示精确来源身份变化，不能直接推断语义证据不同。当前 108 组零极差不能证明尚未运行的新架构“大幅降低随机波动”。

**人工规模。** 仍是一位专家 5 开发＋15 留出，步骤与提取共用；隐藏模型身份和机器总分。已经用来定位问题的确认材料全部属于开发暴露。15 份即使全对，也不是精确的“至少 95% 准确”：在额外假设独立二项抽样时，一侧 95% 下界约为 81.9%，来源相关性还会削弱这种解释。这只是规模说明，不是本项目已观测的结果。

## 10. M8：一致场景下的联合结果与重采样

**真实反例。** 在共同两题上，固定阈值 0.7、C08=32 h 时，C05=14 h 得 Claude−Qwen 的平均 HV 差约 +0.001063；C05=17 h 时为 −0.003743。两模型在这两个场景中仍互不支配。HV 标量排序变了，不等于 Pareto 结论也变了。[八场景实值](../automatic_time_scope/joint_01/summary.json)。

**文献提取。** Multiverse analysis 与 specification curve 适合呈现合理分析选择造成的结果变化；稳健多目标研究提供面对不确定场景时讨论支配关系的理论背景。本报告下面的场景规则是 ClearEval 的设计，不声称等同于某篇论文的全部稳健效率定义。[Steegen 等，2016](https://stat.columbia.edu/~gelman/research/published/multiverse_published.pdf)、[Simonsohn 等，2020](https://www.nature.com/articles/s41562-020-0912-z)、[Ehrgott 等，2014](https://www.sciencedirect.com/science/article/pii/S0377221714002276)。

**拟用模块。** 一个场景包含同一冻结阈值/编码器、参考清单、评分版本和全队列一致的解释约定；答案自己的可选路线按来源分别取分支。先确定相容场景集合，再在同一共同题集比较。不能从不同场景分别挑最高 Com、Cor、Eff 拼成一个不存在的答案。

逐答案计算 `IA=min(Com,Cor,Eff)` 与 `HV=Com×Cor×Eff` 后平均；Pareto 比较的是模型平均 CCE。三维均值的乘积不替代平均逐题 HV。分别报告“全部预设场景均支配”“仅部分场景支配”“所有场景互不支配”。未知分量可给合法范围推导的外界，但外界的每个极值未必同时可实现，不能当作一条真实完整结果。

主 SR/SP 仍保留原值。已有阈值敏感性中，0.6 下 Qwen 支配 Claude，0.7/0.8 下互不支配；0.6 同时存在截断反例，所以不能把它与主阈值视为已经同等验证的选择，更不能按胜负选择阈值。[阈值分析](../automatic_time_scope/threshold_01/summary.json)。

**为什么不靠 2,000 次解决样本少。** 2,000 是 Monte Carlo 重采样次数，不是增加 2,000 份答案，也不改变 SR/SP。两题有序有放回抽两次只有 4 个组合；三题 27 个；五题 3,125 个，可精确枚举以消除 Monte Carlo 抖动。若估计频率约 0.5，2,000 次带来的 Monte Carlo 标准误约 1.12 个百分点；这不是总体估计的标准误。

所有模型必须同步抽同一题或来源块。当前两题共享 FDISCO 来源，按保守依赖图只有一个连通块；一个来源块不能估计来源之间的不确定性。共享来源本身不证明误差相关，但不能用题目重复抽样假装得到多来源证据。[来源审计](../automatic_time_scope/joint_01/source_dependency_audit.json)。

## 11. 可形成的贡献与论文现在仍缺什么

建议先验证三个相互连接的主张：

1. **评分输入保真：** 有来源、角色和作用域的统一表示，能减少错误提取造成的分数变化，并保留局部可计算分项。
2. **必要操作覆盖与合理替代：** 在保留原 SR/SP 的前提下，新增操作实例诊断能区分语言/粒度偏差和真实遗漏，同时在完整相容路线中选择参考。
3. **结论边界可解释：** 将同一答案的提取、参考与时间解释传播到 CCE，揭示何种结论跨设置成立、何种只在特定条件成立。

第一项需要 E1/E3 局部核查；第二项需要 E2 受控删除、等义变换及真实第二路线；第三项需要 E4 稳定性与 E5 共同题集分析。它们目前都是有文献基础的研究假设，没有充分证据支持“首次”“显著优于”或“通用可靠”的措辞。

论文剩余问题不只有专家回执：新职责 Cor 尚未实测；步骤语义适配未冻结；完整替代路线验证还不充分；跨评价器比较及新架构真重复未完成；独立留出需要避开开发暴露；共同题集与来源家族数量不足以支持强泛化结论；E6 没有新增湿实验数据。现有覆盖改善和负结果可以报告，但不能取代这些验证。

实施顺序、逐项消融、可证伪条件及请求计数见 [VALIDATION_PLAN.md](VALIDATION_PLAN.md)。最近似工作的代码和创新边界见 [PRIOR_ART_AUDIT.md](PRIOR_ART_AUDIT.md)。文献阅读范围、发表状态和可用实现见 [SOURCES.json](SOURCES.json)；检索过程见 [SEARCH_LOG.md](SEARCH_LOG.md)。

## 12. 全流程示例：应该在哪里留下什么证据

**例 A：C07 中文答案的覆盖问题。** 原全文及哈希 → 中文操作实例及阶段 → 多语言候选 → 逐参考覆盖证据 → 同一完整参考的原 SR/SP 与补充语义覆盖 → Com/Cor/EGES → 联合结果。已有探针卡在“候选相似”到“独立操作覆盖”的转换：四个参考都命中生成索引 13。新模块需给出实例依据，再判断是否真覆盖；不能因为 SR 升到 4/7 就宣布解决。

**例 B：MAP2–AF488 与原生 GFP。** 原文所选标签 → 类型关系 → 任务范围 → 精确/家族近似知识行 → 适用通道 → 原标签函数 → Eff。现有问题出现在类型、适用性和知识索引三层；未说明抗体链不能自动使已有目标—荧光关系无效。若确实缺适用知识，其他 EGES 与 Cor 分项仍保留。

**例 C：C08 的时间分支。** 原文可选表达 → 必选/可选关系 → 20 h 与 32 h 两个条件输入 → 原 s_time → 两套完整 CCE → 同场景下与另一模型配对比较。问题在分支选择，不是模型不会提取数字；取 26 h 会创造原文没有的执行路线。

**例 D：必要步骤删除。** 固定有依据的基础答案和相容参考集 → 删除每个相容版本都要求的操作及重复表述 → 保存编辑后全文与独立 ID → 用同一配置重跑 M1–M6 → 比较必要覆盖、具体 Cor 判项和 CCE。若结果不响应，依次查编辑是否有效、原步骤是否已低于阈值、是否换了完整参考、提取是否漏看全文、判项量表是否跨档；保存无响应，不能先改阈值把它变成成功案例。

**例 E：最终模型比较。** 全题分项覆盖 → 冻结模型队列 → 共同题集与来源家族 → 一致场景 → 平均 CCE 的 Pareto、平均逐题 IA/HV → 同步配对重采样。当前问题在两题/一个来源依赖块与场景排序翻转，增加 Monte Carlo 次数不能消除它。

本报告依照 academic-research-suite 的深度研究流程完成定向证据综合，采用“本地现象—原文方法—模块假设—验证设计”的顺序。未宣称完成系统综述、独立同行评审或新增科学实验。
