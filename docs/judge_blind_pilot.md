# 重复评分与专家盲评试点

本试点分别检查两件事：同一方案的评分是否稳定，以及输入条件间的分数变化是否与专家对方案质量的判断相符。稳定性不能代替科学有效性。

2026-09-22 实际收集已完成：36 份方案各三次，有效评分 108 条；一次连接失败经保留原记录、核对后补做，实际评分请求 109 次。原始实验使用 v3。观察到 MECA-79 的不同抽取表述引起 PNAd 目标匹配跳变后，另做有来源依据的单规则离线重放，并在收集结束后将生产评分器升级为 `cleareval-fixed-demand-v4-marker-identity`。新身份规则的来源和作用范围记录于 `verified_marker_aliases.py`；v4 重放不是新的一轮教师调用。时间区间抽取、二元裁判项判断和必需/辅助目标的语义仍需进一步校准。

2026-09-22 调用前审查：评分契约升级为 `cleareval-fixed-demand-v3`。修正提示中的非法 JSON、题目范围冲突、重复嵌入的方案文本，并取消要求模型回忆不参与计算的参考耗时。缺少必要抽取字段、字段类型错误、API 截断和非正常结束均为失败。模型明确返回 `null` 则保留该状态；历史缺失值数值政策不因此被宣称有效。新评分与历史评分不得当作同一评估器的重复测量。

运行前重核冻结源文件、方案原文、题目版本和调用顺序。恢复时检查全部已存结果；失败不自动重试或跳过，模型返回版本变化会停止。可用 `--concurrency 3` 在同一轮按冻结顺序发起三个独立请求；一批完成才开始下一批，参数写入运行清单。一份真实成功的接口验证记录计入总数。

标记表使用 `recommended_marker`，未明确标注所有条目的“必选/备选”关系，因此不能统一改为全部必选。v3 记录各参考标记是否匹配及额外标记，但保留原标记评分公式；涉及科学目标覆盖的效度仍需逐题确认。稳定的分数不排除这种系统性偏差。

## 冻结的设计

- 使用 2026-09-13 修订前题目及其历史回答，与固定需求表保持一致。
- 12 个组织/样本层级各随机抽取一道题；抽样种子 `20260921`。抽样依据题目元数据和回答是否存在，不依据已有分数或分差大小。
- 三个模型各分配四道题；每个“题目—模型”组合保留基线、KB-RAG、KB-RAG 与自检三个条件，共 36 份方案。这是小规模分层试点，不估计模型间排名或模型与输入条件的交互。
- 同一教师模型、同一版本及参数，对每份原文独立评分三次，共计划 108 次请求。每次均为新对话，各轮顺序重新随机；不把历史单次评分当成新的重复观测。
- 两位专家各独立评阅 36 份方案，另混入四份相同原文的重复材料。每人共 40 个匿名案例，顺序不同，重复材料至少相隔十个位置。隐藏显示的模型、条件及机器分数；方案文风仍可能让评阅者推测来源。
- 先做一条真实请求验证接口，成功记录计入计划中的 108 次；失败会记录并停止。程序不会默默重复失败请求。

每层级等权抽取，所以试点均值不能直接代替 253 题总体均值。历史自检条件不是从同一初始答案进行的随机配对干预，不能仅凭这里的条件差值宣称自检的因果效果。

## 专家评分

独立总体可行性采用 0–4 分，另记录目标覆盖、标记—方法兼容性、物理/方法学合理性、执行信息完整性、致命问题、把握程度和证据说明。专家可以标记“无法判断”。这些是本次设计的评阅锚点，不声称是已经验证过的标准量表。

请先确认评阅者具备对应领域经验。评阅者在独立提交前不讨论、不查看机器分数和解盲表；可以查阅原始文献并记录 DOI/链接。对于题目已完成或明确排除的步骤，不重复扣分。模型评审不能作为真实专家评分提交。

## 分析

1. **评分波动**：每份方案的应用指数均值、标准差、极差；三轮完整记录的合并组内标准差；抽取方法名不一致的频数。失败请求单独计数，不能当作零质量方案。
2. **条件差异**：先在同一题目—模型内计算 RAG/自检条件减基线的差值，再汇总。以题目—模型为抽样单位做 5,000 次 bootstrap，报告探索性区间，不能把 108 次请求当作 108 个独立题目。
3. **专家一致性**：36 份唯一方案中的两位专家总体评分计算完全一致率与二次加权 κ；隐藏重复材料检查各自一致性，不作为额外独立案例。常量评分使 κ 不可定义时输出空值。
4. **评分与质量的对应关系**：在两名专家完成且教师三次评分完整的方案上，报告机器应用指数与专家总体评分的秩相关；另外比较同题内条件差值的方向一致率，并单独报告平局。两种量表测量内容不同，不把相关当成数值一致性。

区分相关、方法间一致性和重复性，遵循 [Bland 与 Altman 的方法比较讨论](https://pubmed.ncbi.nlm.nih.gov/2868172/)。可靠性指标需要明确观测单位和具体形式，参见 [Koo 与 Li 的可靠性报告指南](https://pubmed.ncbi.nlm.nih.gov/27330520/)。本试点没有预设经专家确认的“足够好”阈值，也不以一次小样本结果宣布评估器有效或无效。

## 运行

使用 Python 3.10 或更新版本，从仓库根目录运行。离线准备和分析只需标准库。

```bash
python experiments/judge_reliability.py prepare --study-dir ../review_artifacts/judge_blind_pilot_2026-09-21
python -m unittest discover -s tests -v
```

`reviewer_A/` 和 `reviewer_B/` 可分别交给专家。打开各自的 `index.html` 评分，保存进度，完成后导出 JSON 或 CSV。也可填写空白 CSV。**不要把 `private/`、研究负责人说明或分析结果交给评阅者。** 原文件、解盲键和抽样表放在 `private/`；保留历史版本，不覆盖已收到的评分。

重复评分命令示例（使用已经配置好的真实接口及密钥环境变量，以下模型名应替换成实际指定版本）：

```bash
python experiments/judge_reliability.py run --study-dir ../review_artifacts/judge_blind_pilot_2026-09-21 --run-dir ../review_artifacts/judge_blind_pilot_2026-09-21/private/judge_run_01 --model YOUR_JUDGE_MODEL --base-url https://YOUR_API_HOST/v1 --api-key-env YOUR_KEY_ENV --temperature 0 --max-calls 1
```

接口验证成功后，去掉 `--max-calls 1` 继续剩余请求。配置和代码哈希不同时拒绝复用同一运行目录。若接口使用 `max_tokens`，加上 `--token-parameter max_tokens`。GPT-5.2 的具体参数组合应以[官方模型文档](https://developers.openai.com/api/docs/models/gpt-5.2)为准；这里只规定参数保持不变，不假定温度为零就绝对确定。

在没有新结果时运行分析，所有待估计分数保持空值：

```bash
python experiments/judge_reliability.py analyze --study-dir ../review_artifacts/judge_blind_pilot_2026-09-21
```

收集完成后的命令：

```bash
python experiments/judge_reliability.py analyze --study-dir ../review_artifacts/judge_blind_pilot_2026-09-21 --run-dir ../review_artifacts/judge_blind_pilot_2026-09-21/private/judge_run_01 --ratings PATH_TO_RATINGS_A.json PATH_TO_RATINGS_B.json
```

每位评阅者只导入一次导出文件；不要同时导入同一人的 JSON 和 CSV。分析会校验包版本和匿名编号，排除无法判断或缺少依据的总体评分，并报告覆盖情况。

现有 `Machine_vs_Human_Summary.json` 是历史资料，240 条记录都缺少评分者和评分时间元数据。这不能证明评分来源或是否盲评，因此不把它当成本轮新收集的独立专家结果。
